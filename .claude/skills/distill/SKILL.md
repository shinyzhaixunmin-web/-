# 蒸馏：资料 → 核心本质知识

目标不是写摘要，而是**找到支撑整本书的那几根柱子**：一句话本质、少数几个核心模型、可以照做的方法。读完成品的人应当能用这本书的思维方式做判断。

## 流程

### 0. 准备
- 确定资料路径（不在 `inbox/` 就先复制进去）和 `<slug>`（小写英文或拼音加连字符）。
- 如果用户同时说明了关注点（例如"只要谈判相关的"），记下来，第 3、4 步向它倾斜，但一句话本质仍然要忠于全书。

### 1. 转文本并分块
```bash
python3 tools/to_text.py inbox/<文件> knowledge/<slug>/_text
```
- 输出分块清单。资料不超过 2 块时，可以跳过第 3 步的逐块笔记，直接精读全文。
- PDF 无法解析时，改用 Read 工具按页读取（每次最多 20 页），每 20 页当作一块。

### 2. 结构扫描
读目录、前言、结论（通常在第一块和最后一块），写出 `knowledge/<slug>/_notes/00_structure.md`：
- 作者想解决的问题、全书主张（初步判断）
- 章节结构，以及章节与 chunk 的对应关系

### 3. 逐块精读（不能跳过，也不能抽样）
每块写一份 `_notes/chunk_NNN.md`，每份不超过 400 字：
- **本块主张**：1–2 句
- **新概念或模型**：名称 + 定义
- **论证或机制**：为什么成立
- **方法或步骤**：如果有
- **反常识点**
- **可引用原句**：≤2 句，注明位置
- **与前文的关系**：推进、补充还是重复（重复的内容标记后不再展开）

块数多（>15）时，可以按顺序每 5 块启动一个并行子代理，各自精读并写笔记，然后由你汇总。给子代理的任务里必须带上本步骤的笔记格式。

### 4. 综合
只基于 `_notes/` 综合，按 `templates/core.md` 写出 `knowledge/<slug>/core.md`：
1. 先写**一句话本质**，再用它检验每个模型：与本质无关的内容降级或删除。
2. 核心模型控制在 3–7 个。如果多于 7 个，说明还没找到更上层的抽象，继续合并。
3. 每条核心内容带出处（章节或 chunk 编号）。
4. 自己的推断、批评、跨书联系只能放在 `> 💡 延伸` 块里。
5. 行动清单必须具体到"明天就能做"。

### 5. 自检（逐条核对，不合格就回去改）
- [ ] 不看原书的人能说出这本书的本质和 3 个以上核心模型
- [ ] 没有"本书讲了……""作者认为很重要"这类空话
- [ ] 每个核心模型都有"怎么用"
- [ ] 所有出处都能在 `_notes/` 中找到对应
- [ ] 成品长度一般为 1500–4000 字（小册子可以更短）

### 6. 交付
- 在对话里给出一句话本质和核心模型列表（不要贴全文），附上 `core.md` 的路径。
- 问用户：要不要把它**生产成技能**（`/forge-skill <slug>`），或者**带着具体问题提炼**（`/extract`）？
