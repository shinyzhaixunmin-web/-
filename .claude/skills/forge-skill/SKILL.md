# 生产技能：知识 → 可执行的技能

知识回答"是什么、为什么"，技能回答"遇到这种情况时**怎么做**"。好的技能能让另一个 Claude 在没读过这本书的情况下，按书中的方法完成任务。

## 流程

### 1. 确定技能的任务
读知识来源，然后回答：
- 这套知识能帮人**完成哪一类具体任务**？（例如"评估一个投资标的""写一封说服性邮件""复盘一次失败项目"）
- 一份知识可以产出多个技能，但每个技能只对应一类任务。任务不明确时，列出 2–3 个候选让用户选。

### 2. 命名与触发描述
- `name`：小写英文加连字符，动词开头更好（如 `evaluate-investment`）。
- `description` 决定 Claude 何时加载这个技能，必须写清：做什么、什么场景、用户可能说出的触发词。控制在 1–3 句。

### 3. 转写（按 `templates/SKILL.md`）
- **模型 → 原则**：改写成祈使句规则，并附一句原因。
- **方法 → 执行流程**：编号步骤，写清每步的输入、判断和输出。
- **反常识 → 反模式**：❌ 常见做法 → ✅ 书中做法。
- **边界 → 何时不用**：写进"何时使用"一节。
- 补一个完整的输入输出示例。
- 删掉背景故事和论证过程，只保留执行需要的内容。正文一般不超过 300 行；参考资料多时放进同目录的 `reference.md`，并在正文中说明何时去读。
- 在开头注明知识来源路径。

### 4. 试用验证
虚构一个真实感强的任务，严格按新技能的流程走一遍：
- 有没有步骤含糊到无法执行？
- 有没有需要判断、但技能没给判断标准的地方？
发现问题就改技能，再试一次。在对话里简要展示试用的输入和结论。

### 5. 交付
- 路径：`skills/<name>/SKILL.md`
- 告诉用户安装方法：把 `skills/<name>/` 复制到任意项目的 `.claude/skills/`（仅该项目可用）或 `~/.claude/skills/`（全局可用），之后用 `/<name>` 调用或由 Claude 自动触发。
