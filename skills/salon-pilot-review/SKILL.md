# 试点复盘（丰田 CI · 验证与固化）

> 知识来源：`knowledge/shiny-ci-dbs-v1/core.md`（模型 1、模型 4 门槛②③、模型 5）
> 前置：最好有 `salon-kaizen-card` 写好的问题卡。没有的话，先向用户补齐问题定义、试点做法和三类指标。

**核心纪律：没有持续验证和人员掌握，不把一次成功当标准。**

## 流程
1. **核对口径**：数据的统计口径是否和试点开始时一致？办卡（预收）有没有被当成业绩？复购有没有固定顾客群？口径不一致时先指出来，不要硬比。
2. **观察窗口到了吗**：没到就只报告"过程指标"的情况，结果写"待观察至 <日期>"，**不下结论**。
3. **排除干扰**：同期客流、人员、季节、促销有没有明显变化？有的话，改用相近的项目或班次做对比，不做简单的前后对比。
4. **逐项判断**：过程指标 → 结果指标 → 保护指标，按下面的规则表得出结论。
5. **检查门槛**：
   - 门槛②（能否固化成标准）：跨过一个完整观察周期仍然有效，并且执行的员工已经掌握（不依赖某一个人）
   - 门槛③（能否复制到别的店）：见下方"推广条件"

## 决策规则
| 情况 | 结论 | 下一步 |
|---|---|---|
| 过程没达标（新做法没执行到位） | **不能判断方案好坏** | 先查培训、工具、负荷，重跑 |
| 过程达标，结果没变化 | **调整**：根因可能错了 | 回去验证备选解释 |
| 结果变好，但保护指标恶化 | **调整**：这是表面改善 | 找出代价的来源再改 |
| 结果变好，保护指标稳定，但观察周期没满或只有个别人做得好 | **继续** | 延长观察期，扩大到更多员工 |
| 结果变好，保护指标稳定，完整周期内持续有效，员工已掌握 | **固化** | 更新标准版本，培训，规划第二家店 |
| 明确无效或代价过大 | **停止** | 把学到的东西写进问题卡，不要简单归为"失败" |

## 推广条件（门槛③，默认值，待用户确认）
- 至少 1 家非标杆店**独立**执行，不由原班人员代做
- 跨过一个完整观察周期
- 结果方向和原店一致，保护指标没有恶化
- 这家店有负责人，能自己带教新员工

四条都满足之前，只能说"已在 X 店验证"，**不能说"可以全面推广"**。

## 输出格式
```
# 试点复盘：<试点名>
- 结论：继续 / 调整 / 停止 / 固化（一句话理由）
- 口径检查：
- 观察窗口：已满 / 未满（到期日）
- 干扰因素与对比方法：
- 指标结果：过程 / 结果 / 保护
- 门槛状态：② 是/否 · ③ 是/否
- 学到了什么：
- 下一步：负责人 / 日期
- 标准更新（固化时填写）：版本号、改了什么、谁来培训
```
